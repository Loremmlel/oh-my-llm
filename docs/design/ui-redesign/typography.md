# 中英文字体与字集方案

日期：2026-10-09。配套[设计基准](README.md)。**已确认字体角色需要区分、中文同样参与设计、允许多个字体打包；下文的具体字族、8105 字方案和构建方式是实施建议，尚未落地。**

## 目标与当前基础

用户接受较大的中文字体文件，允许裁剪后打包多种字体；字集必须明显多于约 3000 字。优先保证中文阅读、混排和内容覆盖，再评估包体。

当前仓库在 `pubspec.yaml` 注册 `Noto Sans SC`，文件为 `assets/fonts/NotoSansSC-VF.ttf`，实测 17,772,300 字节（约 16.95 MiB）。`AppTheme` 将它用于整体 TextTheme。聊天和 Agent 多处 Markdown 样式从 Theme 派生，因此不能只把全局 fontFamily 换成宋体来实现字体分工。

Anthropic 的历史 Styrene／Tiempos 搭配和公开指南的 Poppins／Lora 搭配见[设计依据](README.md#anthropic-的设计依据与本应用的转化)。本项目先以可本地打包的字族制作对照样张，再确定实际使用字体；仅有家族名字不足以确定混排质量。

## 字体角色

| 角色 | 中文候选 | 拉丁字母与数字方向 | 适用区域 |
| --- | --- | --- | --- |
| 界面操作 | Noto Sans SC／思源黑体 | 清晰、偏几何的无衬线；与中文匹配字重和视觉字号 | 导航、按钮、表单标签、模型名、元信息、状态 |
| 阅读正文 | Noto Serif SC／思源宋体 | 人文衬线；Lora 作为对照候选，也比较 CJK 字体内置拉丁字形 | Assistant 长文、小说正文、收藏阅读等连续内容 |
| 页面／作品标题 | 与阅读正文同族优先 | 衬线标题，控制尺寸与字重 | 页面与作品标题；表单内部小标题仍使用界面字体 |
| 内容编辑 | 界面无衬线起步，编辑与预览分工 | 可辨识字符、稳定基线与选择行为 | 聊天草稿、Prompt、模板变量、文档编辑 |
| 代码与技术文本 | 中文按需回退至无衬线 | 等宽字体 | Markdown 代码、正则、协议片段；中文回退不承诺与 ASCII 等宽 |

以上为首轮样张方向。正文宋体是否长期阅读更舒服、标题具体尺度、英文是否需要独立字族，均以真实内容比较。不会给每个区域增加一套字体，也不把所有中文都切成宋体。保留用户字号偏好，不能用更小字号补救空间问题。

实现时优先通过现有主题表达界面样式，另提供明确的阅读／代码样式。聊天、Agent 与收藏复用阅读样式的定义，业务状态与编辑控制器继续由各自 feature 拥有。只在标准 TextTheme 无法表达角色时增加少量主题扩展，不先建设通用字体配置框架。

## 中文裁剪范围

《通用规范汉字表》包含一级 3500 字、二级 3000 字、三级 1605 字。用户提到的 6500 字正好对应前两级；完整字表为 8105 字，三级还包括人名、地名与专门领域用字。来源：[教育部说明](https://www.moe.gov.cn/jyb_xwfb/xw_fbh/moe_2069/s7135/s7562/s7569/201308/t20130827_156353.html)、[字表入口](https://www.moe.gov.cn/jyb_sjzl/ziliao/A19/201306/t20130601_186002.html)。

**建议以完整 8105 字作为新增中文字体的汉字裁剪起点。**小说与自由输入会出现人名、古典用字及模型生成内容，不能仅按当前界面文案取字。8105 是汉字数量，不是最终字体 glyph 数量，也不覆盖全部 Unicode 汉字。

裁剪清单还需要明确加入：

- ASCII 字母、数字、空格及标点；拉丁扩展和拼音声调覆盖按样张清单确定。
- 中文标点、全角标点与数字、引号、破折号、省略号及常用单位符号。
- 应用文案所需的补充字符，以及代码／Markdown 样例中的常用符号。
- 布局所需的组合字形、字体替换与定位信息，不能只按字符数量盲删字体表。

繁体、罕见汉字、外语、emoji 等继续进入明确的字体回退链。裁剪改变显示资产，不得过滤、替换或改写用户文本。系统回退在不同平台的覆盖可能不同，不能承诺任意 Unicode 字符都具有同一外观。

首轮保留现有完整 Noto Sans SC 作为基准和中文后备，新增裁剪后的宋体进行对照。随后再决定是否同时裁剪黑体；体积可接受时，保留完整后备字体是有效选择，不把“所有字体都裁剪”设为硬目标。

Flutter 支持先使用主字体，再按指定的 `fontFamilyFallback` 顺序查找，最后交给平台回退；实际链路需用缺字样例核对。[Flutter 字体回退文档](https://api.flutter.dev/flutter/painting/TextStyle/fontFamilyFallback.html)

## 打包与可复现性

未来引入字体时，将原始来源、版本、SHA256、许可证、字集与生成命令一并记录；发布构建使用仓库内已验证的字体产物，不在启动时从网络取字体。

使用 [fontTools subset](https://fonttools.readthedocs.io/en/latest/subset/index.html) 生成子集。固定工具版本与 Unicode 清单，保留需要的字形替换、定位和中文地区字形特性；对输出 cmap 和清单逐项校验缺字。正文文件的换行不会自动成为 `--text-file` 的保留字符，不能把样本文本扫描当作完整字符规范。

汉字清单以官方字表核对，保存可审查的 Unicode 列表，去重后的主表汉字数必须为 8105；标点和其它字符单列。首次生成还需检查原始字体是否覆盖整份清单，缺字时报告实际差异。

Noto CJK 的 [Sans 许可证](https://github.com/notofonts/noto-cjk/blob/main/Sans/LICENSE) 与 [Serif 许可证](https://github.com/notofonts/noto-cjk/blob/main/Serif/LICENSE) 使用 SIL OFL。引入资产时保留相应版权和许可证，按实际字体的保留名称条款处理子集命名。拉丁候选也需保存各自来源和许可证。

先比较实际使用的常规／强调字重与可变字体版本，再选文件组合。记录每种字体、全部字体以及最终 Windows／Android 产物的大小，不在尚未裁剪时承诺压缩比例。

## 样张与验收

首次字体试验放在聊天与预设编辑两个真实页面中，至少对照：

- 中文小说段落、人名、繁体与罕见汉字、英文术语、URL、数字、中文与英文标点。
- Markdown 标题、列表、引用、表格、行内代码、代码块和推理区域。
- 字重差异、粗体强调、中文／英文基线、标点位置、行高、长标签和用户大字号。
- 浅色与深色、宽屏与窄屏、文字选择、光标、换行、撤销和中文组合输入。
- 字体回退后的字形、行高和性能；不能仅检查是否出现方框。

沿用[长文本输入调查](../../audits/2026-10-06-long-text-editors.md)中的可复现场景与现有 benchmark，比较新旧字体的长文输入和段落布局。保留 `LongTextEditingController` 的 LF 编辑边界、composing 与未修改内容保真行为。既有输入优化的旧数据只作基线线索，不能声称新字体已经具有相同性能。

浏览器用于排版与风格验证；原生 Windows／Android 的性能、IME 和软键盘需另有真实证据。当前不启动原生桌面应用。本次没有下载、裁剪或替换字体，也没有执行上述字体验收。
