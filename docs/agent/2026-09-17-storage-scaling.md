# Agent 长会话存储与列表加载

## 保留范围

继续使用应用的 `chat_history.sqlite`。隐藏、总结及撤回不删除历史正文、模型输入、原生协议续接信息或运行记录。本次不改变 Agent 调度、提示词、剧情状态规则，也不引入文件系统 JSON 仓库。

## 存储变化

schema v21 在原有已发布迁移链末尾追加迁移：

- `agent_sessions.draft` 独立保存输入草稿。自动保存只更新此列，不编码历史，也不会用旧内存快照覆盖之后保存的上下文。
- `agent_history_items` 按作品和内容摘要保存不可变的 JSON 消息，保留原始正文、工具结果和协议私有字段。
- `agent_history_entries` 保存消息与前驱的关系。会话、运行输入和轮前快照以链尾标识引用完整历史。相同前缀共享节点；设定或总结导致前缀改变时，后续相同消息仍共享内容。
- 作品列表只查询 ID 和名称；仅选中作品时读取该会话。
- 子任务查询使用父任务索引，只读取直接子任务，不再读取所属会话的全部运行记录。

文档的当前内容、剧情状态及轮次状态快照仍使用原有表。内容摘要不是文档版本功能；它只用于共享不可变历史内容，不提供新版本浏览入口。

迁移逐条读取旧记录，在同一事务内转换会话、运行和轮次历史。失败时回滚到完整 v20 数据；从最低受支持版本到当前版本的迁移链继续保留。升级后旧应用无法打开 v21 数据库。旧记录释放的页供 SQLite 后续复用，不在启动时自动执行 `VACUUM`，所以已有文件的物理大小未必立即下降。

## 浏览与运行边界

`AgentTranscript` 原本已使用 `ListView.builder`，主视图继续显示最近 50 个根任务及其后代。运行与正文列表可以省略输入历史链；查看某次模型输入时用 `loadRun` 读取完整快照，撤回和状态重试使用完整轮次读取。列表返回的轻量记录不能作为持久化恢复快照使用。

剧情状态页的正文条目改为按可见范围构建；轮次历史初次展开 20 条，按需加载更多。原文和撤回后的记录始终可访问。

这些变化减少历史重复存储和列表的无谓读取，不保证任意长会话的内存恒定：当前会话在构造模型输入时仍需读取历史，正文与状态列表仍持有对应数据，展开一个任务时仍会构建它的执行步骤。若需要进一步优化，应测量真实长会话，再针对这些路径做分页或后台处理。
