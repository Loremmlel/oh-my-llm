# 小说 Agent：子任务写作闭环与批量上下文整理规格

日期：2026-09-16。状态：已实施；本文件保留产品方向与边界，具体工具合同、首版默认值及验证证据见 [Agent 交接文档](../agent/README.md)。

本规格承接[写作、状态更新与撤回规格](2026-09-15-agent-story-state.md)。实施后，写作委派、正文交付、上下文整理采用本文；原规格的三张状态表、原子保存、失败重试、最新一轮撤回和当前资料覆盖保存继续有效。当前实现与历史验证见 [Agent 交接文档](../agent/README.md)，领域词汇见 [CONTEXT.md](../../CONTEXT.md)。

## 1. 目标与范围

让主 Agent 保持连续会话，由写作 Agent 在独立任务中完成写作、派发审查、改稿和状态更新，最终把正文直接交付到主对话。长篇上下文由用户批量整理：用户决定何时处理、处理前面多少楼，以及直接隐藏还是调用总结 Agent 生成摘要。

已确认的约束：

- 主 Agent 保留自己的工具调用、工具结果和原生 Reasoning 续接；不在每轮结束后自动重建成只有正式正文的上下文。
- 每次新建子任务都重新组装独立上下文，不自动继承父任务的完整执行历史，也不接续上一次同职责子任务。一个子任务内部仍正常追加模型回复和工具结果。
- writer 直接派发 reviewer；审查与改稿期间不必经过主模型。通过后由 writer 发起状态更新及正文交付。
- 正文交付成功后，应用结束整轮并默认折叠执行过程，不再请求主模型或 writer 生成工作总结。
- 总结保存在专门的管理窗口中，不作为聊天回复或新的正文楼层。生效摘要放在正文之前。
- 世界书、人物卡仍由用户维护，每轮采用当前内容；文档和模型方案直接覆盖，不恢复修订历史或资料冻结。
- 群像阅读、用户扮演角色及是否代写用户角色的行动，由预设和职责提示词表达，不新增两套产品模式。

本次不实现剧本发现、触发、推进和完成状态，不新增 Shell、动态代码、任意 SQL、操作系统沙箱、RAG、早期剧情分支或任意层级的 Agent 编排平台。用户已表达的“触发后尽量严格执行原剧本”留作后续剧本规格依据，不提前接入本流程。

## 2. 当前实现与目标差异

| 项目 | 当前事实 | 本次目标 |
| --- | --- | --- |
| 主会话 | 重建当前设定前缀，保留后续原生历史 | 保持连续历史，增加前置摘要和用户选择的正文范围 |
| 子任务 | 一次性独立上下文，全部作者设定加委派文本 | 保持每次新建独立，按职责加入正文、摘要、状态与资料范围 |
| 派发 | 仅 coordinator 能 spawn/collect，一层 | 支持 coordinator → writer → reviewer/state；character 按需参与 |
| 写作交付 | 主 Agent 保存正文并调用 update_story_state | writer 完成审查后发起交付，运行器向整轮传播最终正文与终态 |
| 状态提交 | round ID 与主 run ID 绑定，state 必须是主 run 的直属子任务 | 区分整轮归属与直接父任务，保留绑定校验和原子提交 |
| 上下文整理 | 无隐藏范围、摘要职责和摘要持久化 | 用户批量隐藏或总结；原文、剧情状态和实际输入记录保留 |
| 展示与用量 | 已有过程折叠；用量仅累计直属子任务 | 扩展到本次允许的任务树，摘要在独立窗口管理 |

这不是共享三协议客户端的重写。继续复用原生工具调用、续接、取消、用量和现有存储；改变的是 Agent 层的职责、任务归属、上下文选择与交付。

## 3. 职责和任务生命周期

| 职责 | 责任与资料 | 可产生的结果 |
| --- | --- | --- |
| 主 Agent（coordinator） | 理解用户输入、把握当前剧情、决定本轮方向，按需委派角色推演与 writer；保留自身连续历史 | 普通讨论回复、委派任务、本轮创作约束 |
| 写作 Agent（writer） | 根据设定、有效摘要、保留正文、当前状态及委派要求写作；自行派发 reviewer 并改稿 | 候选正文、通过审查的交付正文 |
| 审查 Agent（reviewer） | 对给定稿件检查设定、人物知情、因果、前文、文风与明确禁用要求，提供依据 | 通过，或需要修改的具体问题与建议 |
| 角色 Agent（character） | 在指定身份、场景、动机和资料范围内推演行动与对白 | 候选行为，不能自行成为已发生剧情 |
| 状态 Agent（state） | 根据已绑定的最终正文和更新前状态维护三张表 | 一次原子状态提交 |
| 总结 Agent（summarizer，建议职责名） | 根据用户选定的正式正文范围生成历史摘要 | 总结管理中的摘要，不写剧情状态或正式正文 |

正文写作默认走 writer 闭环；主 Agent 不再承担每次修改意见的转发。普通讨论仍由主 Agent 直接回复，不强制产生正文轮次。角色推演按需使用，不要求每轮派发所有人物。

每次新的 reviewer 调用也使用新上下文；writer 可以明确提供上一轮意见、修改说明和当前稿件，而不是复制上一轮 reviewer 的全部历史。同一次 writer 任务保留自己的多次写作、工具调用和审查反馈。

权限按职责执行。writer 可保存普通候选文档、派发审查和发起交付；reviewer、character、summarizer 不获得剧情写入权；state 仅能读取绑定状态并提交增量。主 Agent 既有普通文档能力不等于跳过正文交付合同。

只支持本流程需要的派发关系，不因引入多级任务就开放任意递归。同步与后台调用可沿用现有接口；依赖子结果的父任务必须等待真实终态。收取权限按直接委派关系检查，不能因为任务同属一个作品就收取任意子任务。

## 4. 写作、审查和交付

1. 主 Agent 接收用户输入、当前设定与状态，确定任务，按需调用 character，再委派 writer。
2. writer 独立组装上下文并撰写候选正文。候选稿仍可覆盖修改，不更新剧情状态。
3. writer 将当前完整稿件和审查要求交给 reviewer。reviewer 获得必要设定、前文和状态，不需要读 writer 的完整思考过程。
4. reviewer 返回明确结论。阻止交付的问题需指出稿件内容、依据和原因；纯粹的审美偏好与不确定推测作为建议标明，不能伪装成确定错误。
5. writer 判断反馈并修改；存在未解决的阻止交付问题时继续审查。最终采用稿必须与通过结论所针对的稿件一致，后续修改不能沿用旧稿结论。
6. writer 发起交付，应用绑定最终正文、更新前状态和本轮身份，派发独立 state。state 只依据绑定输入提交一次增量变化，不继承草稿与审查争论。
7. 状态保存成功后，运行器将正式正文和完成结果传播到 writer 及本轮主任务，直接结束本轮。无需再请求任何模型写结束语。

建议把“启动状态更新、等待提交、交付正文、结束整轮”封装为 writer 的一个交付工具，沿用或调整现有 update_story_state；工具最终名称和参数在实现时确定。即便拆成多个内部动作，也不增加“数据库已经提交后，还依赖下一次模型调用结束”的窗口。

审查应能表达通过或需要修改，并绑定实际稿件；内部内容标识或内容比较不构成用户可见的文档版本系统。程序校验的是审查与稿件关联、工具权限和保存条件，不能宣称程序证明了作品没有 OOC 或逻辑错误。

审查和改稿受整轮预算限制。到达上限仍未通过时保存候选稿与原因，不伪造通过，不无限循环。状态更新失败时继续使用现有“待更新 → 单独重试或放弃”的行为；提交成功后的停止或通知失败不能把已提交剧情降级为未保存。

主 Agent 的 spawn/collect 往返仍须真实闭合。交付结束不能遗留未配对的工具调用、未收尾的兄弟任务或仍可写入的迟到子任务。同一回复中交付后尚未执行的冲突操作应被明确拒绝并记录结果，不能继续改写已采用正文。

## 5. 主会话和子任务上下文

### 5.1 主 Agent 保持连续历史

逻辑组成顺序如下；工具定义仍经各协议原生工具字段提供，不靠拼接文字授予权限。

```text
Harness：职责提示词、执行合同及原生工具定义
适用预设
当前世界书、人物卡
当前生效的历史摘要（如有）
保留的主会话历史：用户输入、正式正文、原生回复、工具调用与结果、Reasoning 续接
本轮最新剧情状态与用户输入
```

- 每轮刷新设定前缀，接受用户编辑设定造成的缓存变化。世界书和人物卡分别使用 XML 区域，区域内按稳定顺序组织，人物卡以 Markdown 标题区分人物；正文作为资料，不获得工具权限。
- 主 Agent 自己的工具调用、工具结果、原生 Reasoning 和普通讨论继续保留。原生私有续接内容按现有共享层保存，不用显示出来的推理摘要替代。
- 不每轮自动新建主会话，不自动删除草稿或过去工具结果，不把历史中的状态结果反复改写为最新值。
- 最新状态在每次用户轮次开始时作为明确的当前快照提供一次，位于历史后部；本轮内只追加工具往返，状态更新完成后在下一轮提供新快照。快照标明适用轮次，模型以最新快照为准。
- 本轮用户输入和普通讨论正常留在主会话。只选择隐藏正文不能顺便删除用户的创作要求或闲谈。
- 预览与真实请求使用同一组装规则；历史“实际输入”始终展示当时保存的内容，不被之后的摘要或隐藏操作重写。

### 5.2 子任务每次新建独立组装

| 职责 | 设定 | 正文与摘要 | 剧情状态 |
| --- | --- | --- | --- |
| writer | 世界书、完整人物卡、适用预设 | 当前生效摘要和用户保留的正式正文 | 本轮当前完整状态 |
| reviewer | 审查所需的作者设定和预设 | 当前稿件、有关正式正文与摘要；不复制 writer 的完整执行历史 | 审查所需状态 |
| character | 世界书、对应角色卡或已有新人物资料 | 由任务明确提供的相关内容；不能默认给全知视角的全部前文 | 指定人物及场景相关的局部状态 |
| state | 必要作者设定、状态维护规则 | 绑定的最终正文与原始用户任务 | 更新前完整状态快照 |
| summarizer | 总结职责提示词；必要设定只作理解辅助 | 用户选定范围及关联写作输入，按来源顺序提供 | 不用当前状态补造较早范围内的事实 |

子任务可见的资料、状态和正文范围也要约束读取工具。初始输入裁剪之后，不能通过通用 read_document/read_story_state 又取回范围外的全部内容。范围应由应用验证并绑定任务，不依赖模型在自由文本中自称某个身份。

角色局部信息由已有作者资料、状态和本次委派产生，不要求用户恢复一套手工维护的角色视角副本。完整世界书、自己的人物卡或某一状态行仍可能含角色未知信息；仅按人物或行过滤不等于严格知情隔离。角色视图的具体规则见第 11 节，未实现相应裁剪前不得宣称已经隔离秘密。

所有子任务共用本轮一致的输入依据；进行中的稿件不能提前进入其他子任务的“已发生正文”。同一子任务内继续保留原生工具循环，重置只发生在新建任务时。

### 5.3 正文的独立定位与原生历史保留

正式楼层继续保存不可变的采用正文快照。新流程建议让交付工具和完成子任务结果返回楼层标识与状态，由应用把最终正文作为独立、可定位的上下文块提供给主 Agent；避免仅为逐层交付而重复携带全文，也不要求模型逐层复述正文。追加正文时先闭合相关原生工具往返，不伪造模型原生回复或推理。

这不改变“保留主 Agent 原生历史”的要求。模型主动读取文档时的全文工具结果、历史 writer 返回的全文、推理中引用的片段都可能形成正文副本。默认批量操作只处理可明确定位的正式正文块，不对原生工具参数、结果或 Reasoning 做字符串搜索替换，也不自动删除整轮工具历史。

因此，隐藏某楼并不承诺正文所有内容从模型输入中消失；仍有原生副本时，管理窗口和输入预览应说明保留情况，不能虚报释放的上下文。对旧会话不能可靠独立定位的全文也应如实显示限制。若将来要移除这些副本，需要另行确定完整原生往返的处理方式；不能以“压缩”为由默认推翻本规格的保留原则。

## 6. 用户控制的批量隐藏与总结

用户在空闲时进入总结管理，选择当前会话前面的一段正式楼层，执行“直接隐藏”或“总结并替代”。是否处理、处理多少由用户决定。楼数按成功保存的正文轮次计算，模型调用、改稿次数、普通讨论、失败任务、总结任务均不增加小说楼数。

建议首版采用从较早未处理正文开始的连续范围，并允许恢复原文参与上下文；不引入任意重叠区间组合器。选择使用稳定楼层标识和真实顺序，不依赖页面当前加载的 50 条记录。建议允许设置楼数提醒，未设置时仅提供手动入口；到达阈值只提醒，不自动调用模型或改变输入。

| 操作 | 执行 | 成功后的下一次输入 | 失败或停止 |
| --- | --- | --- | --- |
| 直接隐藏 | 应用保存选定范围，不调用模型 | 选定正式正文块不再发送，不生成摘要 | 保持之前的输入选择 |
| 总结并替代 | 启动独立总结任务，结果保存到总结管理 | 摘要在前，所覆盖正式正文块不再重复发送 | 保持原文范围和旧摘要生效，可重试 |
| 恢复原文 | 恢复指定批次覆盖的正文参与上下文 | 对应摘要退出生效范围，避免同一批全文与摘要无意重复 | 保持之前的输入选择 |

原文、运行记录和剧情数据库不被删除。隐藏与总结都不撤销已发生剧情、不回滚数据库、不改变正式正文。窗口中的正文预览只是阅读资料，不等于重新加入模型输入。

例如已有 20 楼，用户总结第 1—12 楼：成功后使用“第 1—12 楼摘要＋第 13—20 楼正文”，同时保留主会话其余原生历史、当前设定与最新状态。直接隐藏同一区间则不添加摘要。两种方式都受第 5.3 节的原生副本限制。

## 7. 总结 Agent 与总结管理窗口

### 7.1 总结任务

- 由用户在管理窗口直接发起，不先请求主模型批准或生成转发指令。复用独立子任务的调用、停止、记录和用量能力，不为挂载任务而伪造一条主会话用户消息。
- 新增总结职责的模型与提示词配置，未单独选模型时继承主模型。建议默认不套用要求续写或角色扮演的创作预设，仍允许用户在现有职责配置机制中选择适用预设。
- 输入绑定选定的正式楼层及这些轮次的用户写作输入。只把范围内的事实、约束、人物变化、重要对白或伏笔作为总结依据，明确区分事实、角色判断和未兑现安排。
- 不继承主 Agent 或 writer 的完整历史，不总结废稿、工具日志、Reasoning 或审查争论；不把较后楼层或最新状态倒灌进早期摘要。
- 总结不能写剧情状态、正文或作者设定。它只返回摘要，由应用校验来源仍有效后保存。
- 摘要保存与对应正文范围退出默认输入必须一起生效。用户选择“总结并替代”后，成功结果直接应用，不再交给主 Agent 审批。空结果、异常终态、取消、保存失败或来源失效时不能先隐藏原文。重启后不自动重跑模型。
- 保留来源范围，方便回看原文。后续重新总结优先使用原始正式正文，不能默默把反复压缩旧摘要作为唯一信息来源。

### 7.2 专门窗口

从 Agent 页提供“总结管理”入口。窗口管理当前会话的摘要和隐藏批次，显示当前生效的总结、覆盖楼层、哪些原文仍参与上下文，以及任务状态。

建议支持查看和编辑当前摘要、保存覆盖、重新总结、恢复原文参与上下文；保留现有直接覆盖语义，不增加摘要改稿版本浏览。若有多个生效批次，按来源顺序展示并放到正文前，避免重叠覆盖；不自动合并或再次压缩旧摘要。

总结可以在窗口内生成和显示，但不向主对话追加模型回复、小说正文或完成总结。错误和重试入口留在窗口内，运行时停止可达；关闭窗口不等于取消任务，重开可看当前进度。

窗口沿用现有 Material 主题、长文可选择复制、键盘和窄屏行为。摘要编辑与资料编辑一样，标题、范围和动作区固定，长文本区域拥有滚动。只读查看不触发模型调用，不增加不必要的确认步骤。

## 8. 任务归属、保存和撤回

必须区分直接父任务、本轮主任务、实际写作任务和状态任务。可以在现有记录上增加最少关联，不要求新建通用工作流框架。

- writer 写入的普通文档仍归属整轮，整轮撤回可以恢复这轮仍拥有的写入；用户后来手动保存的内容继续保留。
- 允许 state 的直接父任务为 writer，但必须验证它属于本轮、绑定指定稿件、仍在运行，并持有该轮状态提交权限。仅放松 parentId 检查而取消绑定校验不符合要求。
- 正式正文、状态变化及撤回快照沿用一次保存语义。同一提交重放返回已有结果，停止后的迟到结果不能写入。
- 重试状态更新只启动绑定的 state，不重写正文、不重审已经绑定的稿件，也不重新调用主模型；保留用户后来输入的草稿。
- 停止覆盖整棵当前任务树；调用预算与时长按整轮累计，不能因多级派发而绕过上限。并发计数需避免等待子结果的父任务占满执行名额。
- 总结是会话级上下文整理操作，不是小说轮次。摘要、覆盖关系和隐藏选择按会话保存；剧情状态继续按作品共享，不因其他会话的摘要操作改变。
- 同作品执行写作或总结期间，维持现有单任务保护。可查看管理窗口，来源修改、撤回和上下文选择切换在空闲时执行，避免生成期间悄悄更换依据。

撤回最新一轮时，正文与状态按原规格恢复，排除该轮的续写历史。与此同时校验摘要来源：如果生效摘要覆盖了被撤回的正文，整批摘要失效，仍有效的其他来源正文恢复参与输入，不能保留包含已撤回剧情的摘要继续写作；原摘要可在管理窗口标为失效供查看。

撤回不能简单恢复一份旧会话快照并覆盖用户后来做的全部总结选择。与被撤回正文无关的摘要和隐藏选择应保留，只调整受影响的来源关联。重复撤回、恢复原文和重复总结都以实际楼层标识校验。

继续保留数据格式版本、已发布 schema 迁移、实际输入记录和必要的撤回／过期校验。新增数据通过顺序迁移加入，不能通过删除旧会话或重新写入历史来规避兼容问题。

## 9. 阅读展示与成本观察

主对话默认交付完整正式正文。writer 和主任务关联同一份交付结果，展开执行过程仍可查看本层推理、工具、子任务与错误；不让模型重新生成相同正文用于上层显示。

reviewer、character、state、summarizer 的结果有各自用途，不计入小说楼数，也不冒充正式正文。审查意见和状态更新过程通过对应任务查看；摘要的主要阅读与编辑入口始终是总结管理。

现有“选定正文后收起过程、状态失败时仍可见重试／放弃”的行为保留。多级任务需要正确返回直接父任务、查看所属主轮次，并累计所有后代用量；窗口内总结任务单独显示自身用量，不混成一次小说交付。

前缀、工具目录和摘要顺序保持稳定。一轮内追加原生工具往返，摘要仅在用户操作成功时切换；不逐调用重写摘要、状态或状态栏。资料修改和批量整理可以改变缓存前缀，界面不承诺固定命中率。比较实际发送内容、调用量、已报告缓存读写、等待时间和写作效果，不能只看缓存占比。

已有用户提示词不因新增职责而被静默覆盖。默认职责提示词和固定执行合同应反映新流程；旧提示词中的“一层、仅主 Agent 可交付”等描述不能扩大或覆盖当前工具权限。总结职责为旧配置提供可解释的默认值，保留用户已有职责模型与预设选择。

### 10.2 验收场景

1. 连续写两轮，主 Agent 第二轮仍带第一轮自身的原生调用、工具结果与 Reasoning 续接；不会因交付自动变成纯正文会话。
2. 第二次启动 writer 使用新上下文，没有上一次 writer 的草稿和审查日志；同一次 writer 内的审查反馈和工具循环正常保留。新 reviewer 同理。
3. writer 直接启动 reviewer，经历一次修改后通过，再发起 state；主模型在此期间无需转发意见，提交后也没有多余总结调用。
4. 通过结论绑定实际稿件；改动后不能沿用旧结论交付。反馈含无依据意见时不盲目当作事实，预算耗尽不伪造通过。
5. writer 写入、状态提交、停止、失败重试、重启和最新轮撤回都保持原有数据保障；迟到任务、错误归属和重复提交不能产生错误写入。
6. 角色任务只获得绑定的资料和状态范围，读取工具不能绕过；完整作者秘密是否隔离按第 11 节确定的能力验证，不能以行过滤测试声称语义隔离。
7. 世界书和人物卡修改后下一轮生效，使用规定的区域与稳定顺序；不增加资料版本操作。预设可分别控制群像与角色扮演。
8. 20 楼选择前 12 楼直接隐藏，不调用模型、不改变剧情状态，后续输入按选择排除可定位的正文块，原文仍可查看并恢复。
9. 同一区间选择总结，独立任务成功后原子应用摘要与覆盖范围；摘要位于正文前，只显示在管理窗口，不增加聊天回复或小说楼层。
10. 总结失败、取消、空结果或保存失败，旧输入选择仍有效；重复点击和重启不重复生成或重复应用。重新总结能读取原始正式正文。
11. 原生工具结果已有正文副本时保留原始内容和合法续接，管理窗口如实说明；不能通过 UI 已隐藏就断言模型已看不到该内容。
12. 恢复原文不会无意重复发送同批摘要与全文；撤回摘要来源楼层时，关联摘要失效且不继续携带已撤回剧情，无关整理选择保留。
13. 超过 50 条运行记录后仍能选择真实的旧正文范围；子任务、讨论和失败任务不混入楼数。所有后代用量计入对应任务树，总结用量独立可见。
14. 主会话预览与实际输入一致，历史实际输入不受后续整理影响；三种协议仍保留合法的工具调用／结果配对及原生续接。
15. 桌面、窄屏和键盘弹出时，总结窗口可读可编辑、操作和停止可达；错误保留在相关界面，关闭窗口后运行状态仍可找回。

测试按合同主 owner 分层：上下文选择归组装／纯规则，任务归属与取消归 runtime，原子应用与撤回归 store，UI 测用户交互；集成层验证真实 wiring，不重复各层完整矩阵。实施时执行格式、静态分析、架构门禁和必要测试，日志按仓库规则进入 `logs/`。模拟测试不能替代真实写作的审查误报、状态遗漏、总结损失和成本试用。

## 11. 建议默认值与尚未定下的边界

以下未被用户逐项指定，不能在交接中写成已确认的额外需求：

- **楼数阈值、处理数量与摘要长度**：没有固定数值。建议默认仅提供手动操作；提醒阈值可选，覆盖范围每次由用户选择，摘要口径通过总结职责提示词调整。
- **多批摘要组织**：建议按非重叠来源范围分别保存、按顺序注入，重做某批时直接覆盖当前结果；不自动合并旧摘要，也不新增版本浏览。
- **原生历史中正文副本的进一步压缩**：已确认必须保留主 Agent 原生历史，其中的正文副本是否应随楼层排除尚未确定。首版采用第 5.3 节的保留默认值；若要更彻底释放这部分上下文，应另行约定，不能悄悄裁剪整轮 Reasoning 或工具结果。
- **角色“局部可见”的粒度**：已确认对应角色卡和局部状态的方向，具体如何处理混合人物卡、共享状态单元格、世界书秘密与全知前文尚待细化。先实现可核对的任务资料范围，完整语义知情隔离不能仅凭提示词或行筛选宣称完成。

本规格的建议项不自动视为全部落地：首版采用手动批量整理、非重叠连续范围、保留原生副本和显式角色资料范围；没有新增楼数提醒或严格语义知情隔离。实际实现与验证以交接文档为准。
