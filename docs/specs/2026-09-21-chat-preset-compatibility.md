# Chat 预设适配、上下文查看与紧凑布局规格

日期：2026-09-21。状态：待实现。本轮只编写规格，不修改运行时功能。本规格以本轮讨论为准；早期调查中关于人物绑定、Agent 和数据库推进的建议不构成本次范围。

## 目标与边界

让收集到的 SillyTavern 写作预设能够保留原有条目，在 Chat 中通过有限宏组合提示词，并能查看展开后的请求上下文。继续使用现有的排序、标题、启停、角色和三个注入位置。

已确认的原则：

- 变量在请求准备时求值。保留原条目及其原文，不提前展平、拆分、重命名或生成汇总条目。
- **从不处理标题关键词。** “选一”“别关”“教程”“模式”等标题只供用户理解、分类和选择；不据此建立互斥组、联动开关、隐藏条目或删除正文。重命名标题不得改变请求结果。
- `{{user}}` 是一个内置特殊替换，固定展开为小写字面量 `user`。不新增人物名称设置，也不创建一个能够被排序或关闭的隐藏条目。
- 不适配人物卡、世界书、Persona、外部记忆、全局变量、前端美化、输出正则、扩展脚本和交互选项运行机制。Chat 原有检查点功能照常工作。
- Agent 和数据库推进不在本规格范围。不得把有限宏解释器接入 Agent，或将含宏预设静默展平后宣称可用于 Agent。
- 普通正文中的文风、格式、模型适配和选项输出要求仍按原启用状态导入。是否保留这些要求由用户决定，不从标题或正文推断应关闭哪个条目。

## 调查依据

调查了 `D:\personal\预设` 中 8 份 Chat JSON，共 1,186 个 `prompts`。统计只覆盖普通条目正文，不包含 JavaScript、正则、顶层辅助格式字段，也不等于模型效果验证。

| 语法 | 全部条目中的次数 | 选定顺序表启用条目中的次数 | 本次用途 |
| --- | ---: | ---: | --- |
| `setvar` | 784 | 374 | 设置文风、视角、写作约束等片段 |
| `getvar` | 466 | 249 | 在汇总条目中读取片段 |
| `addvar` | 16 | 8 | 梦鲸预设追加文风和限制 |
| `user` | 112 | 17 | 用户称呼占位 |
| `//` 注释 | 70 | 10 | 不发送的说明 |
| `trim` | 14 | 7 | 去掉宏附近的换行 |
| `lastUserMessage` | 11 | 4 | 在尾部条目中再次引用最新用户输入 |

这些是词法出现次数，包含教程和示例；启用统计采用各样本 `character_id=100001` 的顺序表，不把多个顺序表合并。所有样本均有空的 `chatHistory` 结构条目，普通正文中没有发现 `{{chatHistory}}` 宏。

`lastUserMessage` 的实际用法包括 Izumi 的 `<Master_input>`、狐狐预设的 `<User_latest_request>` 和梦鲸写作模式的 `<dreamer_input>` 包装。它们将最新输入复制到另一段提示词内，原始用户消息仍然存在。

本规格选取固定、有限的宏语义。SillyTavern 官方同时存在新旧引擎差异，不能因支持相同宏名就宣称完整兼容；现代引擎的宏名不区分大小写，支持先处理内层宏。[SillyTavern 宏文档](https://docs.sillytavern.app/usage/core-concepts/macros/)

## 导入与原始数据

### 入口与字段

设置的“预设”列表增加 SillyTavern JSON 导入入口，复用现有文件选择、导入结果与预设编辑流程。它不是通用设置恢复入口，不导入服务商、模型参数、API 配置或扩展对象。

| 来源 | 本应用含义 |
| --- | --- |
| 文件名 | 新预设名称的默认值，用户可以修改 |
| `prompts[].name` | 原样保存为条目标题 |
| `prompts[].content` | 原样保存为条目正文，包括宏和空正文 |
| `prompts[].role` | 映射到现有 system / user / assistant |
| `identifier` | 保存为可选的来源标识，用于关联、报告和定位 |
| 选定 `prompt_order[].order` | 条目求值顺序及初始启用状态 |
| 结构 marker 与注入字段 | 仅用于确定可表达的注入位置、顺序及兼容性诊断 |

应用为导入的预设和普通条目分配自身 ID，不用源 identifier 作为跨文件唯一键。重复导入产生新的预设，不覆盖已有预设或用户修改。

`prompt_order` 只有一个有效列表时直接使用；多个有效列表时让用户选择一个，显示来源 ID 和条目数。可以预选 `100001`，但不得把它当成普遍适用的格式规则。缺少有效顺序表时展示导入问题，不猜测全体启用。

开关以选定 `order[].enabled` 为准，不用 `prompts[].enabled` 覆盖。缺失或错误类型的必要字段、重复 identifier、顺序表引用缺失条目等问题都定位到来源，不能静默覆盖。具体接受的缺省字段及其默认值必须由真实样本和官方实现建立 fixture 后固定。

未加入选定顺序表的普通条目作为备用条目追加到末尾，默认关闭，保留原标题和正文。空标题不按正文或功能重新命名；编辑器可以显示现有的无标题占位文字。

### 结构条目

- 仅当 `marker == true` 且 identifier 匹配已知结构标识时，按结构条目处理。标题相同不构成识别条件。
- `chatHistory` 消耗为导入位置锚点，不生成空提示词，也不创建历史文本副本。导入不会授予它关闭 Chat 历史的能力；来源中关闭历史的配置需报告差异。
- 人物卡、世界书、Persona 等已知宿主 marker 不生成本应用虚构内容；列入“未导入的动态来源”。
- 未知 marker 或带有意外正文的 marker 必须在导入结果中呈现，不静默丢弃正文。用户可以将其正文作为普通条目保存并自行指定位置。
- 普通条目即使名为“人物设定”“世界书”或 identifier 类似宿主字段，也不据此丢弃。
- 顶层 `scenario_format`、`personality_format`、扩展脚本、正则及其它宿主配置不转成普通提示词。非空的生成类型限制、预填充等无法表达的配置单独报告，不声称已经生效。

导入结果说明导入数量、备用条目数量、位置映射和不支持的来源。普通条目的不支持宏不阻止保存；结构缺失导致无法定位时，先让用户指定位置再完成保存。整个流程不按标题做选择。

## 注入位置与发送顺序

### 三种位置

普通发送和编辑后发送的目标顺序为：

```text
检查点记忆（system，可选）
前置预设条目
有效历史消息（不含本次最新输入）
最新输入前的预设条目
本次最新用户输入
后置预设条目
```

“最新输入前”和“后置”的边界是本次最新输入本身，与 `lastUserMessage` 宏出现在哪个条目无关。

| SillyTavern 结构 | 映射 | 说明 |
| --- | --- | --- |
| Relative，即 `injection_position=0`，位于 `chatHistory` 前 | `before` | 忽略该条目的 depth 字段 |
| Relative，位于 `chatHistory` 后 | `after` | 历史本身包含最新输入，所以这是最新输入之后 |
| In-Chat，即 `injection_position=1`，depth=1 | `beforeLatestInput` | 只在本次上下文最后一条是目标用户输入时等价 |
| In-Chat，depth=0 | `after` | 位于历史末尾之后 |
| 其它位置或 depth | 不自动猜测 | 显示原值，由用户选择现有三种位置之一 |

Relative 与 In-Chat 的区别，以及同 role、depth 的 Order 排序来自官方 Prompt Manager；不能因为样本中的普通条目带有默认 depth=4 就按深度插入。[SillyTavern Prompt Manager 文档](https://docs.sillytavern.app/usage/prompts/prompt-manager/)

### 求值顺序与注入顺序分开

变量按预设当前条目列表顺序求值；初次导入保持选定 `prompt_order` 的顺序。最终消息按注入位置组装。禁止先按前置、最新输入前、后置分组再执行宏。

In-Chat 同深度的来源排序不能覆盖求值顺序。导入器需计算最终注入顺序：保留 Relative 顺序；depth=0 的内容位于 Relative 后置条目前；同深度按来源的角色分组及 `injection_order` 排序，平局保持来源顺序。原条目仍各自保持角色与正文，不在导入时合并为一个新条目。具体跨角色排列和缺省 Order 在实现时用官方源码及混合角色 fixture 固定，不能只验证单角色样本。

存储可使用每条消息可选的 `importInsertionOrder` 保存同一位置内的导入排序；缺省按当前列表顺序。它不参与宏求值。用户主动拖动条目时，该条目所在注入位置恢复为当前列表顺序，清除该位置的导入排序；修改注入位置时，新旧位置均恢复为当前列表顺序。编辑器在有来源排序时用简短提示说明，并可通过上下文查看实际顺序。标题、正文和开关修改不重置排序。

### 当前实现需要纠正的行为

`chat_request_message_builder.dart` 目前先追加全部会话消息，再追加 `beforeLatestInput`，使“最新输入前”实际落在最新输入之后。现有对应测试也固定了这一错误顺序。实现本规格时必须纠正，并补修复前失败、修复后通过的证据；不能仅让导入器迁就错误位置。

最新输入由请求准备阶段显式识别，不通过扫描拼接后的 user 角色消息寻找：预设本身也可以使用 user 角色。

| 请求类型 | 最新输入与历史边界 |
| --- | --- |
| 正常发送 | 当前准备发送的用户消息；历史在它之前 |
| 编辑后发送 | 编辑后的新消息；只保留该新分支祖先，不带原分支后续回复 |
| 重试最新回复 | 重试目标对应的请求输入；不带被重试的 assistant 回复 |
| 固定顺序步骤 | 复用该步骤实际准备发送的输入，不将输入框草稿混入 |
| 检查点总结 | 以实际追加的总结指令作为本次输入；原检查点指令和记忆顺序保留 |

过滤、排除与检查点裁剪必须先确定有效上下文。显式排除或已被检查点替代的文本不能因宏读取重新进入请求。缺少有效目标输入时，不随意拿旧分支的消息补位。

本次不增加 ST 的 Continue、Impersonate 等生成模式。若一个既有调用不具备“末条是目标 user”的边界，不能宣称 depth=1 完全等价；必须在该入口使用明确的本应用规则并显示兼容性差异。

## 有限宏语言

### 首批支持

宏只在明确启用 `sillyTavernSubsetV1` 语法的预设正文内执行。普通预设继续采用 `plain`，原有 `{{...}}` 不会因升级自动变为可执行语法。

| 语法 | 本应用语义 |
| --- | --- |
| `{{setvar::key::value}}` | 将 value 写入本次环境，覆盖同名值；自身输出空字符串 |
| `{{getvar::key}}` | 原位输出本次环境中的值；未定义时输出空字符串并记录诊断 |
| `{{addvar::key::value}}` | 首批支持样本所需的文本追加，不自动加空格或换行；未定义视为空文本；自身输出空字符串 |
| `{{user}}` | 固定输出 `user` |
| `{{lastUserMessage}}` | 输出本次有效上下文的最新用户输入正文 |
| `{{// 注释内容}}` | 删除完整注释；可跨行，内部不执行宏 |
| `{{trim}}` | 删除该宏以及紧邻它的连续换行；不对整条正文调用 trim，不删除正文内部空格 |

`addvar` 的数值运算不属于本批样本需要的能力。遇到数值追加用法，报告“不支持数值 addvar”，保留该表达式、不修改变量；不把数值相加静默做成字符串拼接。混合数字和文本仍作为文本追加。这个限制应在语法帮助中明确，不声称实现 ST 的完整 addvar。

词法规则：

- 宏名不区分大小写；变量键保留大小写，`Name` 与 `name` 不自动合并。
- 首批带参宏支持样本使用的 `::` 形式；不顺带实现单冒号、空格参数、变量简写、块语法或宏 flags。
- 支持多行值及括号配对的嵌套。解析分隔符时必须尊重嵌套层级；setvar/addvar 在 key 后的剩余参数文本作为 value，正文中的 `::` 不被任意丢弃。
- 宏名和键周围的语法空白可以忽略；value 正文的空白保留，除非显式使用 `trim`。不对变量值自动去缩进或补换行。
- 同一条目从左到右求值；嵌套参数先求值，再执行外层宏。注释与不支持宏的内部不执行副作用。
- 宏返回的字符串直接拼入结果，不作为新模板再次扫描。历史正文、输入正文和图片信息也不执行宏。

### 环境与空结果

每次请求从空变量表开始，只执行当前启用的条目。关闭条目不赋值、不追加；不能先执行关闭条目再只隐藏输出。

一次求值只执行一遍条目，不提取并提前执行 setvar，不建立全局变量数据库，不跨轮保存残值，不在多轮替换中等候变量“最终有值”。重试、切换会话、切换预设和独立预览都使用各自的环境。

纯赋值、纯注释和展开后仅含空白的条目不生成 API 消息；同时有赋值和正文的条目正常输出剩余正文。是否为空只决定是否发送，不修改存储的原文。

例如：

```text
条目 A：{{setvar::style::简洁}}
条目 B：{{addvar::style::，避免套话}}
条目 C：写作要求：{{getvar::style}}

只有 C 产生消息：写作要求：简洁，避免套话
关闭 B 后，C 产生消息：写作要求：简洁
```

### lastUserMessage 的边界

这是普通条目里的文本宏，不是结构条目，也不决定任何注入位置。它不会消费或替代原始用户消息，重复出现就重复输出，不自动去重。

正常发送使用当前用户消息最终正文；如输入来自本应用的表单模板，先完成原生模板处理，再将其结果当作普通文本提供给此宏。编辑使用编辑后正文；重试使用目标分支正文。输入里即使写着 `{{setvar::x::...}}`，也只被当作文本插入。

该宏只复制正文，不复制图片附件、推理文本、显示用模板分段标记或消息元数据。纯图片输入会得到空文本，图片仍由原始用户消息发送。当前任务没有显式新输入时，仅可读取有效、未排除、未被检查点替代的历史中的最新 user 正文；没有则为空，并在预览中解释来源缺失。

### 不支持的语法与错误

不支持 `char`、`charIfNotGroup`、`chat`、人物卡字段、世界书出口、外部记忆宏、`getglobalvar` 等全局变量、`random`、`roll`、日期时间、条件、循环、EJS 和 JavaScript 执行。`chatHistory` 只作为导入结构锚点，不新增 `{{chatHistory}}` 宏。

未知或明确不支持的完整宏保留原文，并记录条目、原始表达式及原因。用户可以继续使用、修改或关闭该条目；不弹逐项批准框，不暗中替换为空。未知宏包裹的内层宏也保持原样，避免出现只执行一部分的副作用。

未定义 getvar 与未知宏分开呈现：前者是可选变量未赋值的提示，后者是语法不支持。诊断按条目和表达式聚合，避免数百条重复提示淹没正文。

已支持宏的缺失参数、不配对括号及超过资源上限属于解析错误：保留原文和草稿，停止该次请求准备，显示条目内诊断。不能发送半截求值结果。导入可以保存待修正的预设，不自动禁用条目。

解释器须有命名的深度、操作数和展开长度上限，超限明确失败；实现时根据样本上界选择常量并验证边界，不新增用户资源设置页。输出长度不能在达到上限时静默截断。

### 必须核对的真实依赖

梦鲸的部分条目先把 `getvar(sleep_dream_protocol)` 嵌套写入另一个变量，后续条目才追加 protocol，最后再读取前一个变量。按本规格的即时求值，后续追加不会追溯改变早先保存的字符串。

实现时需用这一最小结构和真实节选对照，明确展示实际结果。若作者依赖旧引擎的延后替换，应标为部分兼容，由用户改写或调整条目；不得偷偷预执行后续条目或增加无限递归。`72.json` 主要依赖 JX Runtime，其普通条目可提取导入，但本功能不承诺恢复脚本运行效果。

## 查看当前上下文

### 查看什么

Chat 增加“查看当前上下文”入口。内容来自实际发送路径的公共准备结果，至少包含有序消息、来源信息和诊断；展示层不维护第二套宏解释器或字符串拼接逻辑。

| 页面状态 | 打开时展示的内容 | 页面标识 |
| --- | --- | --- |
| 空闲且有可发送草稿 | 当前配置下发送该草稿所用的上下文 | 请求预览 · 包含未发送草稿 |
| 编辑消息 | 编辑完成后形成新分支的请求上下文 | 请求预览 · 编辑后的输入 |
| 空闲且无草稿 | 当前有效历史、检查点和预设的上下文预览 | 上下文预览 · 未加入新输入 |
| 正在生成或等待自动重试 | 当前调用准备完成时的不可变消息快照 | 本次请求 · 已准备 / 已发送 |
| 预览准备失败 | 已有诊断及错误来源，不能伪装成完整请求 | 无法完成预览 |

无草稿时不创建空 user 消息，“最新输入前”的条目展示在有效历史末尾，并注明尚未加入新输入；它不能被称为未来输入已经确定的完整请求。输入框含未完成表单或正在处理图片时，显示相同准备限制，保留原草稿。

生成状态标识来自 coordinator 的真实阶段，不因有快照就称为已经发送。准备尚未完成时显示准备中；不把不断增长的 assistant 回复追加进该次输入快照。当前调用的快照只在内存中随运行生命周期保留，本次不建立历史请求数据库。

点击打开时获取一次快照，关闭后重开才刷新；阅读时不因流式响应、用户返回页面修改设置而跳动。查看与复制不发起模型调用，不修改消息树、草稿、开关、变量或检查点。

### 读者能看到什么

- 顶部摘要：会话、预设、查看状态、消息数、文本字符数。字符数不得标为 Token，不用未经核实的比例估算 Token。
- 消息按最终组装顺序排列，每段显示序号、role、来源（检查点、预设条目、历史消息或当前输入）。预设来源显示原标题及映射位置，标题只是界面标签，不发送给模型。
- 正文展示完整展开后的纯文本，可选择、可复制；不渲染预设要求生成的 HTML，也不执行脚本。正文顺序不能因界面分组而改变。
- 图片显示附件名称、类型等已有元数据，明确属于哪条消息；不把 base64 填满页面或复制为“正文”。推理内容只有确实属于请求时才可列入，不能混入 Chat 的普通正文。
- 诊断默认折叠并显示数量；可定位未定义变量、不支持宏、解析错误和只赋值而未生成消息的条目。不添加一个可编辑的全局变量管理器。
- 提供“复制全部文本”和单条复制。复制结果带角色、来源分隔和图片占位说明，明确是可读文本，不是假装完整 HTTP JSON。

本页面查看 Chat 发送给生成适配器的消息，不承诺是厂商收到的原始 HTTP 报文。Messages 等协议后续可能提取 system、合并同角色或编码图文；页面用简短说明标明这一层次，不显示 API key、Header 或传输日志。不为查看入口额外记录请求正文到日志。

### 手机与桌面布局

按父级可用宽度使用现有 `AppBreakpoints` 和 `AppAdaptiveActions`，不根据 Android/Windows 标签分流，不新增一套响应式断点。

手机通常落入紧凑布局：顶部保留对话标题及“更多”“侧栏”两个页面动作。现有侧栏按钮继续由 `AppShellScaffold` 提供，位置不重复添加；编辑状态已有的返回/取消入口保留。

```text
紧凑顶部：[对话标题…………] [更多 ⋮] [侧栏]

更多菜单：
  新建对话
  查看当前上下文
  对话检查点
  修改对话标题
```

侧栏原有的“新建对话”按钮继续保留。发送、停止仍在输入区，不搬到顶部；模型和预设选择继续沿用既有入口。新建、检查点、重命名保留既有忙碌状态限制，上下文查看在生成时仍可使用。

宽布局直接提供“新建对话”“查看当前上下文”“对话检查点”，将低频“修改对话标题”收进更多菜单，再由 shell 提供侧栏按钮。使用既有图标、Tooltip、颜色和命中区域；空间不足进入紧凑动作集，不缩小按钮挤出空间。

上下文阅读在紧凑布局使用可返回的整页视图，宽布局使用有最大宽高限制的阅读面板。消息正文是唯一主滚动区域；标题与关闭/返回控件持续可见。长行允许换行，大字号不遮挡操作。

这是当前页面的只读临时查看，不持久化 UI 控制器。实现沿用项目的导航/自适应覆盖层规范，禁止另建 `MaterialPageRoute` 平行栈或通过路由 extra 传领域对象。支持系统返回、Escape、键盘焦点及关闭后回到原触发入口；不得影响未发送草稿和编辑事务。

## 手机侧栏选中背景越界

用户报告：Chat 对话侧栏中，当前会话的主色背景在滚动时越过列表容器，覆盖列表外区域。

静态检查发现 `ConversationHistoryPanel` 的行使用 `ListTile.tileColor`，行内没有 Material，背景可能绘制在列表视口以外的 Drawer Material 上。Flutter 文档说明这些颜色由祖先 Material 绘制；这是优先排查的原因，尚未经过本轮设备复现。[Flutter ListTile 文档](https://api.flutter.dev/flutter/material/ListTile-class.html)

实现要求：

- 让列表行背景及点击墨水的绘制层位于滚动裁剪边界内，优先在列表视口内使用合适的局部 Material，或使用会随条目被视口裁剪的背景。仅给 ListTile 外包 ClipRect，若仍由外层 Material 画背景，不能视为已解决。
- 裁剪整个列表视口即可满足上下边界要求；行圆角和点击反馈也需正确，避免为每个列表祖先重复加裁剪层。
- 保持选中主色、圆角、会话点击、滚动位置恢复、历史/预设标签切换与侧栏开关行为。
- 在实际窄视口把选中项分别滚过顶部和底部，覆盖慢拖、快速滑动、切换选中项和重新打开侧栏。主色背景与点击反馈都不得覆盖页签、新建按钮或容器之外。
- 共享列表组件如受影响，验证其它调用方；不顺带重写所有历史页布局。本项应独立于宏支持交付。

## 实现归属与持久化

| 职责 | 归属与约束 |
| --- | --- |
| ST JSON 识别及结构转换 | settings 的导入边界；产出原生预设和结构诊断，不执行宏或扩展脚本 |
| 有限语法解析、求值 | 可独立测试的纯 Dart 逻辑，供 Chat 请求准备调用；不依赖 UI、网络或数据库 |
| 有效历史、最新输入、检查点与请求快照 | Chat application；生成入口和查看入口共享规则，生命周期继续归 coordinator |
| 三个注入位置及来源记录 | 现有 request builder 扩展，不能另起一套仅用于预览的构建器 |
| 导入提示及上下文页面 | 各自 feature presentation，只读 application 输出 |
| 顶部动作收纳 | Chat 使用既有 AppAdaptiveActions；shell 继续独占侧栏按钮 |
| 背景裁剪 | ConversationHistoryPanel 的局部绘制边界，保留共享列表职责 |

`PresetPrompt` 增加明确语法版本，旧数据默认 `plain`，新导入使用 `sillyTavernSubsetV1`。来源 identifier 和可选注入排序属于条目元数据，不能写进标题或正文。原生表单 `TemplatePrompt` 与多条消息的 `PresetPrompt` 继续分开，不合并两种模板语言。

SQLite 当前仓储将消息列表单独存入 `messages_json`，不能只改 PresetPrompt.toJson 就认为语法字段已落库。语法版本应增加明确持久化字段和下一步顺序迁移；条目元数据通过消息 JSON 编解码保留。导出、导入、备份和预设同步均需携带语法版本，不允许降级丢字段后把宏作为普通文本发送。

已有数据缺少新字段时保持 plain；未知显式语法版本拒绝使用并说明原因。设置交换版本按现有支持范围升级；已发布 SQLite 迁移不退役。往返验证必须经过真实 repository 和交换边界，不能只测模型 toJson/fromJson。

## 验收与交付拆分

### 宏和导入

- 纯规则测试承担多行嵌套、求值顺序、开关、覆盖、追加、空结果、不支持宏、括号错误及资源上限矩阵。
- 同样正文只修改标题，输出完全一致；标题含“选一”的两个条目同时开启时仍同时执行。
- 不同会话、不同预设、重试和预览之间无变量残留；被插入的用户文本不能触发宏副作用。
- 小型 JSON fixtures 覆盖多个顺序表、顺序表开关优先、备用条目、结构 marker、Relative 默认 depth、depth=0/1、混合 role/Order、未支持位置及格式错误。
- 真实样本至少检查 Izumi 的变量汇总、轻量狐狐的嵌套 user、梦鲸的 addvar 和延后依赖、梁元的两种深度。保留作者原始文件，不将整个大型预设或脚本复制进测试仓库。
- 兼容结论按条目及受支持语法给出，不能用“JSON 导入成功”替代完整运行效果验证。

### 请求与查看

- request builder 是注入顺序的主测试 owner；补强现有错误顺序测试，验证最新输入位于 beforeLatestInput 与 after 之间。
- 分支、排除及检查点边界在其 application owner 验证；上层只保留一条预览与实际准备结果相同的真实 wiring 路径，不重复整个矩阵。
- 查看页验证更多菜单入口、草稿/编辑状态提示、复制、诊断、关闭返回与不修改草稿。流式情况下验证展示的是当前请求快照，不含正在生成的回复。
- 持久化和交换层验证旧预设默认 plain、新字段往返保留及未知语法版本拒绝，不将此矩阵复制到页面测试。

### 界面与侧栏

在窄视口、宽视口和大字号下验证顶部动作与上下文阅读，检查标题空间、返回、焦点、复制、长正文和图片占位。侧栏背景问题通过真实滚动复现与修复前后视觉证据验证；不添加只断言 widget 属性或像素坐标的脆弱测试。

实现提交应按独立结果拆分：注入顺序纠正；预设导入及宏支持；上下文查看及顶部动作收纳；侧栏背景裁剪。迁移、交换与对应测试随所需功能提交。可先交付上下文查看和侧栏修复，但尚无宏支持时，查看页必须如实显示当时的原始提示词，不能假装已经展开。
