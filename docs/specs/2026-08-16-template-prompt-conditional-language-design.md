# 模板提示词单选变量与条件分支设计

日期：2026-08-16
状态：已确认，待实施计划

## 1. 背景

模板提示词当前支持以下占位符：

- `{{变量名}}`：文本变量；
- `{{变量名:number}}`：整数变量；
- `{{正文}}`：聊天页主输入框对应的保留变量。

模板由用户在聊天输入区手动选择。选择后，聊天页展示额外变量控件；发送时，`templated_user_message_builder.dart` 将正文和变量值渲染成最终用户消息，并把模板 ID 与变量值保存在消息元数据中。

本设计在不改变模板触发方式的前提下增加：

1. 单选变量；
2. `if / else if / else` 条件分支；
3. 根据当前有效分支动态显示变量控件；
4. 新增、编辑模板页中的可折叠语法说明。

## 2. 目标

- 使用简洁、适合多行自然语言提示词的块语法表达条件分支。
- 让设置页变量识别、聊天页动态字段和最终消息渲染共用同一套模板语义。
- 保持现有文本变量、数字变量、正文插入、消息编辑和草稿恢复行为兼容。
- 在保存、导入和聊天发送边界明确拒绝无效模板，避免静默生成错误提示词。
- 保持模板数据可导出、可同步，并让不理解新语法的旧版本明确拒绝新格式。

## 3. 非目标

第一版不实现：

- 模板引用或模板套模板；
- `if` 块嵌套；
- `and`、`or`、`not`、括号等组合条件；
- 变量与变量之间的比较；
- 模板自动匹配或 `/模板名` 触发；
- 设置页或聊天页的渲染预览；
- 仅声明但不插入值的变量语法；
- 单选选项中的 `|` 转义；
- 将形如 `{{...}}` 的完整双花括号片段转义为字面文本。

## 4. 触发与整体交互

模板继续沿用现有手动触发方式：

1. 用户在聊天输入区的模板下拉框中选择一个模板；
2. 聊天页显示条件控制变量及当前有效分支所需的变量；
3. 用户修改变量值时，聊天页重新计算有效分支；
4. 用户点击发送时，模板引擎生成最终用户消息；
5. 正文、模板 ID 和全部变量值进入现有消息发送与持久化流程。

切换模板只影响下一次发送，不改变正在进行的生成请求。

## 5. 变量语法

### 5.1 文本、数字与正文

现有语法保持不变：

```text
{{主角名字}}
{{章节数:number}}
{{正文}}
```

- 未携带类型标记的变量默认为 `text`。
- `number` 只接受十进制整数，包括负整数。
- 新建数字变量的默认值继续为 `1`。
- 聊天页中无法解析为整数的当前数字输入属于字段错误，发送被拒绝。

### 5.2 单选变量

单选变量使用 `|` 内联声明选项：

```text
{{人称:select|一|二|三}}
```

规则：

- `select` 后至少有两个非空选项；
- 选项按声明顺序展示；
- 每个选项去除两端空白；
- 去除两端空白后不允许出现重复选项；
- 第一版不允许选项内容包含 `|`；
- 选项显示文本与插入模板的值相同，不区分 label/value；
- 新建变量时默认选择第一个选项；
- 设置页允许从选项列表中修改默认选项；
- 选项变更后，旧默认值若仍存在则保留，否则回落到第一个选项。

带类型的占位符同时承担变量声明和插入值。后续位置使用普通占位符复用该变量：

```text
接下来用第{{人称:select|一|二|三}}人称撰写。
当前选择：{{人称}}
```

变量声明在整个模板内统一解析，不要求带类型的声明先于普通引用出现。同名变量出现多个带类型声明时，类型及单选选项必须完全一致；否则模板无效。

### 5.3 正文变量限制

`{{正文}}` 继续对应聊天页主输入框：

- 不允许声明为 `number` 或 `select`；
- 只能出现在条件块之外；
- 模板存在顶层 `{{正文}}` 时，正文插入该位置；
- 模板没有 `{{正文}}` 时，保持现有行为，将非空正文和换行放在模板内容之前。

禁止把 `{{正文}}` 放入条件分支，避免切换分支后主输入框内容被意外丢弃。

## 6. 条件块语法

### 6.1 基本形式

```text
{{#if 人称 == "一"}}
以“我”的口吻叙述，主角名为{{主角名字}}。
{{else if 人称 == "二"}}
以“你”的口吻叙述。
{{else}}
使用第三人称叙述。
{{/if}}
```

一个条件块包含：

- 一个必需的 `{{#if 条件}}`；
- 零个或多个 `{{else if 条件}}`；
- 零个或一个 `{{else}}`，且必须位于最后；
- 一个必需的 `{{/if}}`。

从上到下判断，只渲染第一个成立的分支。没有 `else` 且所有条件均不成立时，该条件块输出空字符串。

第一版允许同一模板中存在多个并列条件块，但不允许条件块内部再出现条件块。所有分支都必须完成语法和变量校验，不能因为当前分支未生效而忽略错误。

### 6.2 条件表达式

条件固定为：

```text
变量名 比较运算符 字面量
```

支持范围：

| 变量类型 | 支持的运算符 | 右值 |
| --- | --- | --- |
| `text` | `==`、`!=` | 双引号字符串 |
| `select` | `==`、`!=` | 双引号字符串，且必须是已声明选项 |
| `number` | `==`、`!=`、`>`、`>=`、`<`、`<=` | 十进制整数 |

示例：

```text
{{#if 人称 == "一"}}
第一人称要求。
{{/if}}

{{#if 章节数 >= 2}}
将内容拆分为多章。
{{/if}}
```

字符串字面量允许使用 `\"` 表示双引号、`\\` 表示反斜杠；第一版不支持其他转义。编译器保留双引号内部的全部字符，不去除字符串字面量两端空白；运行时变量使用去除输入两端空白后的有效值，因此 `" 一 "` 不会匹配有效值 `"一"`。字符串比较区分大小写。数字比较先将有效值严格解析为整数。

条件只能引用模板中已声明的变量。条件本身不声明变量；变量之间不能互相比较。

### 6.3 有效值

模板求值使用变量的有效值：

1. 聊天草稿中存在非空输入时，使用去除两端空白后的输入；
2. 输入为空时，回落到模板中保存的默认值；
3. `select` 的有效值必须属于其选项列表；
4. `number` 的有效值必须是合法整数；
5. `{{正文}}` 使用主输入框去除两端空白后的内容，不设置默认值。

运行时有效值不满足变量类型时，聊天页在对应字段 inline 显示错误并拒绝发送，不尝试猜测或选择其他分支。

## 7. 控制标签与换行

控制标签独占一行时，该标签行及其行结束符不进入渲染结果：

```text
写作要求：
{{#if 人称 == "一"}}
使用第一人称。
{{else}}
使用第三人称。
{{/if}}
正文如下：
{{正文}}
```

选择“一”后输出：

```text
写作要求：
使用第一人称。
正文如下：
……
```

“独占一行”指控制标签所在行除空白字符外没有其他内容。裁剪范围是该行的全部前导空白、控制标签、尾随空白及其行结束符，不留下仅包含缩进的空白行。该规则适用于 `if`、`else if`、`else` 和 `/if`。

例如，下列带缩进的控制标签仍按独占行处理；分支正文自身的两个前导空格属于普通文本并予以保留：

```text
写作要求：
  {{#if 人称 == "一"}}
  使用第一人称。
  {{/if}}
```

控制标签与正文位于同一行时，只移除标签本身，标签外的空格和换行严格按模板原文保留：

```text
视角：{{#if 人称 == "一"}}第一人称{{else}}第三人称{{/if}}。
```

变量占位符不触发独占行裁剪。

## 8. 模板编译与求值结构

模板能力由 Settings domain 中的一套纯 Dart 模板语言组件承载，不依赖 Flutter、Riverpod 或持久化实现。

### 8.1 编译

编译器接收模板正文，生成不可变的 `TemplatePromptProgram`。程序由以下节点组成：

- 文本节点；
- 变量插值节点；
- 条件块节点及其有序分支。

编译结果同时包含：

- 按首次出现顺序排列的变量规格；
- 变量名、类型、选项之间的一致性结果；
- 控制条件引用的变量集合；
- 顶层是否显式包含 `{{正文}}`；
- 带稳定错误码、源码位置和简体中文原因的语法诊断。

每个诊断使用不可变的 `TemplatePromptDiagnostic` 表达，至少包含 `TemplatePromptErrorCode code`、源码 offset、行号、列号和面向用户的简体中文消息。domain 测试断言稳定错误码与位置；Widget 测试只断言对用户可见的错误说明和禁止保存行为，避免把界面测试耦合到内部枚举。

设置页、聊天页和消息构建器必须调用同一编译器，不能分别维护正则替换规则。

### 8.2 求值

求值器接收已编译程序、正文和变量值，返回：

- 最终渲染文本；
- 用于现有消息气泡分段展示的正文/模板片段；
- 当前有效分支；
- 当前应显示的输入变量；
- 运行时值错误。

聊天页选择模板时编译一次。变量值变化只重新求值，不重复解析模板。发送时复用当前模板对应的编译结果，并由现有 `templated_user_message_builder.dart` 统一形成 `TemplatedUserMessage`。

若模板在选择后被设置页更新，聊天页以 Provider 提供的最新不可变 `TemplatePrompt` 重新编译，不能继续使用旧正文的编译结果。

## 9. 动态变量字段

聊天页需要显示的输入变量为：

1. 出现在任一 `if` 或 `else if` 条件中的控制变量；
2. 出现在顶层文本中的变量；
3. 出现在当前有效分支中的变量。

`{{正文}}` 继续使用主输入框，不进入额外变量字段列表。其他变量按模板中的首次出现顺序展示。

字段类型：

- `text`：现有文本输入框；
- `number`：现有数字微调控件；
- `select`：下拉单选框。

切换条件后，不再有效的字段从界面隐藏，但其控制器值和会话草稿值保留。切回原分支时恢复原值，不回落默认值。发送和消息持久化保存全部变量的有效值，包括当前隐藏分支中的值，以便编辑已发送消息时恢复。

编辑已发送消息时，先恢复消息保存的模板 ID 和变量值，再使用当前模板定义重新求值。模板定义新增的变量使用当前默认值；已删除变量的旧值不再展示或参与渲染。

若消息或会话草稿中保存的 `select` 字符串值已不在当前选项列表中，则在字段绑定阶段回落到当前模板配置的默认选项，并把归一化后的值写回当前编辑草稿。这里不能无条件选择第一个选项，因为用户可能在设置页显式配置了其他默认选项；选项协调流程保证当前默认值始终有效。正常展示下拉框供用户重新选择。若绕过字段绑定后仍出现无效值，发送边界继续按运行时值错误拒绝。

## 10. 设置页设计

新增和编辑模板继续复用现有表单。正文变化经过现有防抖窗口后执行编译和变量协调。

变量默认值区域按类型显示：

- 文本变量显示默认值输入框；
- 数字变量显示整数默认值输入框；
- 单选变量显示默认选项下拉框；
- `正文` 只显示主输入框说明。

### 10.1 可折叠语法说明

表单增加一个默认收起的“模板语法说明”区域。新增和编辑场景复用同一个独立组件，每次打开表单均恢复收起状态，不持久化展开偏好。

展开内容包含：

- 文本、数字、单选和正文占位符示例；
- 一个简短的完整条件块示例；
- 字符串需双引号、数字不需引号；
- `select` 使用 `|` 分隔选项；
- 分支内可以使用普通变量；
- 独占行控制标签不会留下空白行；
- 第一版不支持嵌套条件、组合条件和模板引用；
- 当前版本不支持在单选选项中使用 `|`，也不支持把完整的 `{{...}}` 片段转义为字面文本。

说明区不提供语法插入、交互式编辑或渲染预览。

### 10.2 语法诊断

编译错误在模板正文输入框下方 inline 展示，格式包含行号、列号和简体中文原因，例如：

```text
第 4 行第 1 列：缺少与 {{#if}} 对应的 {{/if}}
```

存在任一错误时禁止保存。至少覆盖以下错误：

- 未闭合、缺少开始标签或顺序错误的条件标签；
- `else` 后继续出现 `else if`，或同一块出现多个 `else`；
- 嵌套条件块；
- 条件引用未声明变量；
- 不适用于变量类型的运算符或字面量；
- 同名变量类型或单选选项冲突；
- 单选项不足、为空、重复或包含 `|`；
- `{{正文}}` 携带类型或位于条件分支中。

用户正在编辑时，即使内容无效也保留正文和已有默认值输入，不因一次解析失败清空表单。

## 11. 聊天页错误处理

正常设置流程只会保存通过编译的模板。为了防止旧本地数据、导入数据或损坏数据绕过设置页，聊天页仍必须处理编译失败：

- 在模板变量区域 inline 显示“模板语法无效，请到设置中修正”及首个诊断；
- 禁止使用该模板发送；
- 不使用 SnackBar 或 Dialog；
- 用户可以切换为“不使用模板”继续发送普通消息。

运行时数字或单选值无效时，错误附着在对应字段并阻止发送。模板求值不允许部分成功，也不把未解析标签原样发给模型。

最终求值文本去除两端空白后为空时，保持现有空消息拒绝行为。

## 12. 持久化与兼容性

### 12.1 本地存储

`TemplatePromptVariableType` 增加 `select`，`TemplatePromptVariable` 增加不可变选项列表。JSON 增加可选 `options` 字段。

现有 `template_prompts.variables_json` 可以承载新增字段，因此不增加 SQLite 列、不提升 `PRAGMA user_version`。旧 JSON：

- 缺少 `type` 时按 `text` 读取；
- `text`、`number` 缺少 `options` 时按空列表读取；
- `select` 缺少合法选项时视为无效模板，不静默降级为文本变量。

消息继续保存最终正文、模板 ID 和 `Map<String, String>` 变量值，不改变消息表结构，也不持久化编译程序。`select` 保存选项的字符串值而不是列表索引；调整选项顺序后，只要该字符串仍在选项列表中，历史值就继续有效。

### 12.2 设置导出格式

设置导出格式从 v7 升级为 v8。虽然新增变量字段本身可以被旧 JSON 解码器忽略，但旧应用会把条件标签当成普通变量并可能把多个分支一起发送，因此必须通过版本边界阻止错误降级。

- v8 导出包含新变量类型和选项字段；
- 新版本继续支持 v5 至 v8；
- v7→v8 迁移只提升格式版本，不改写旧模板正文；
- v8 数据由旧版本按未来格式明确拒绝；
- 当前版本数据在解码后、写入前编译所有模板，任一模板无效时将数据报告为 malformed，不执行部分模板写入；
- 剪贴板导入与受认证 Sync snapshot 使用相同 Settings codec 和验证规则。

本设计不承诺应用降级后直接读取已写入新语法的本地数据库；受支持的跨版本交换边界是版本化的设置导入导出和 Sync snapshot。当前旧实现会把未知变量类型回退为 `text`，因此没有证据表明新增 `options` 字段本身会导致启动或反序列化崩溃；实际风险是旧模板解析器不理解条件控制标签，可能保留多个分支正文并生成错误消息。新版本无法为用户随后安装的旧二进制补上解析能力，因此包含该功能的发版说明必须明确提示：保存条件模板后不要降级并继续使用同一份本地数据库。

## 13. 测试策略

### 13.1 编译与模型单元测试

- 文本、数字、单选和正文变量规格提取；
- 带类型声明位于普通引用之后时仍正确协调；
- 单选选项 trim、顺序、默认值保留与失效回落；
- 同名变量声明冲突；
- 条件块、`else if`、`else` 和多个并列块；
- 禁止嵌套及各类标签顺序错误；
- 条件运算符、字面量类型和未声明变量诊断；
- 稳定错误码及 offset、行号、列号定位；
- `select` 变量 JSON round-trip 与旧 JSON 兼容。

### 13.2 求值单元测试

- 文本、单选相等与不等判断；
- 数字六种比较运算；
- 按顺序选择首个成立分支；
- 没有匹配且没有 `else` 时输出空内容；
- 分支内变量插入；
- 有效值回落默认值；
- 非法运行时值拒绝；
- 无缩进和带缩进的独占行控制标签整行裁剪，以及 inline 标签空白保留；
- 字符串字面量空白按原文保留，变量有效值去除两端空白；
- `{{正文}}` 顶层插入及无正文占位符时的现有前置行为。

### 13.3 应用与 Widget 测试

- 消息构建器只输出有效分支且不泄漏控制标签；
- 正文/模板消息片段分类保持正确；
- 设置表单生成单选默认值下拉框；
- 设置表单展示精确 inline 诊断并阻止保存；
- 可折叠语法说明默认收起、点击展开；
- 聊天页显示条件控制变量和当前分支变量；
- 切换单选后字段切换且隐藏值保留；
- 编辑消息恢复模板选择、变量值和有效字段，失效单选值回落当前默认选项；
- 无效模板 inline 报错并禁止发送；
- v7→v8 导入、v8 round-trip、未来版本拒绝及无效模板拒绝。
- 消息变量元数据保存单选字符串值，不依赖选项索引。

实现时先为编译器、求值器和关键聊天行为建立失败用例，再实现最小通过代码；缺陷回归证据按仓库规则保存到 `logs/`。

## 14. 验收标准

1. 用户可在模板中声明 `{{变量:select|...}}`，聊天页显示单选控件并插入选择值。
2. 用户可用已确认的块语法表达 `if / else if / else`，最终消息只包含首个成立分支。
3. 当前分支变量动态显示，隐藏值在同一会话草稿和消息编辑流程中保持。
4. 独占行控制标签不产生额外空白行，inline 控制标签保留作者编写的外部空白。
5. 无效模板不能从设置页保存、导入边界写入或聊天页发送。
6. 新增、编辑模板页提供默认收起的简明语法说明，不增加预览。
7. 现有文本变量、数字变量、正文插入、模板选择、消息编辑和模板元数据持久化行为不退化。
8. 本地 schema 不迁移；设置格式升级到 v8，并保持 v5 至 v7 的受支持迁移路径。
