# Agent 覆盖式重试、用户消息编辑与会话职责

## 已实现：最新主 Agent 回复重试

主执行流最新回复旁提供“重试”，确认后使用原用户指令重新执行整棵任务树，保留任务 ID 和原位置。旧回复、旧子任务和旧正文轮次被覆盖，不提供版本切换；当前未发送草稿保留。失败或停止后可以再次重试。

撤回与清空在同一个 SQLite 事务内完成：剧情表恢复轮前内容，revision 继续递增以拒绝过期结果；工具文档通过 `agent_document_undo` 恢复；原生工具历史和剧本进度恢复到运行前。相关总结批次失效，不能把旧正文摘要重新放进上下文。事务失败则原回复、文档、状态和子任务全部保留。重试已经启动后模型失败，显示新失败结果，不复活被覆盖的回复。

约束：仅作品最新主任务允许重试。其他会话已经运行后，旧会话的最新回复不能覆盖共享工作区的后续成果；子任务和总结任务不提供此入口。用户后来手动保存的文档仍归用户所有，不被本轮撤回覆盖。已有正式正文的历史任务复用正文轮次快照；没有任何运行前快照的旧记录显式拒绝重试。新增任务总是保存运行前快照，复用已有 JSON 历史链去重，无需数据库 schema 迁移。

这里“不保留版本”指没有旧回复／子任务／轮次可切换；既有不可变历史存储可能留有不可达的去重片段，并非安全擦除。总结管理保留失效批次供识别来源，失效摘要不再参与模型输入。

主要实现：`agent_workspace_controller.dart` 的发送流程、`agent_runtime.dart` 的主任务检查点、`sqlite_agent_store.dart` 的 `resetLatestReply` / `_withdrawStoryRound`，以及 `AgentTranscript`。

## 用户消息编辑：需要绑定和回退记录，不必建立分支版本系统

如果规则是“修改某条主 Agent 用户消息，永久丢弃该节点之后的全部内容”，数据结构可以保持线性。必须能确定用户任务边界，以及它开始前的正文、剧情状态、原生上下文和剧本进度；无需同时保存多个可切换版本。

现有基础已经具备大部分绑定：

| 数据 | 现有归属和回退依据 |
| --- | --- |
| 用户指令与助手回复 | `AgentRunRecord.prompt` 与同一根任务 ID |
| 子任务 | `parentId` / `rootRunId` |
| 正式正文和剧情表 | `AgentStoryRound.id` 与根任务相同，含 before/after 状态 |
| 工具写入文档 | `source_run_id` 和 `agent_document_undo` 的首次写入前快照 |
| 会话历史、剧本进度 | 主任务 `beforeWorkspace`，旧正式正文也有轮前快照 |
| 压缩摘要 | `AgentContextBatch.roundIds` 来源集合 |

后续开发需要补齐的是“按目标任务截断后缀”的单个原子操作：按作品提交顺序从后向前恢复文档和状态，删除目标任务之后的根任务及后代，使与删除范围相交的摘要失效，恢复目标任务前的会话历史与进度，写入修改后的用户指令再生成。手工改正文、改设定是否也随时间回退，必须成为明确产品规则；当前工具撤回不会撤销用户后来手改的内容。

跨会话是关键：若 A1 → B1 → A2 都写同一作品，编辑 A1 却只删除 A2，会留下依赖旧 A1 的 B1。可选择作品级全局截断（连同其他会话后续内容一起丢弃），或者为每个会话／分支提供独立正文和状态。后者才需要真正的分支工作区和版本管理。仅给每份文档增加一个版本号不能解决依赖关系。

推荐先简化为一部作品一条创作时间线，再做任意用户节点的线性回退。此次不实现任意节点编辑，也不改变现有会话数据结构。

## 会话调查：当前隔离的是模型上下文，不是创作成果

| 范围 | 当前拥有的数据 |
| --- | --- |
| 作品共享 | 工作文档、世界书、人物卡、剧本全文、剧情状态、保存的配置方案 |
| 会话独立 | 历史输入、输入草稿、采用的配置快照、剧本已读信息和进度、总结批次、任务列表 |

`_newSession` 使用相同作品 ID、新会话 ID 和空历史建立会话；没有克隆工作文档或剧情表。`refreshAgentWorkspace` 每轮读取作品当前世界书与人物卡，`AgentRuntime.run` 每轮注入当前剧情状态。切回旧会话只恢复旧对话，不恢复当时的世界。写作与审稿子 Agent 的正式正文／总结取当前会话的轮次，另一会话的正文不会自动完整注入。

新会话目前有三个实际用途：

1. 更换模型、协议、端点或规则。已有历史含原生工具和推理重放数据，控制器拒绝把它们直接迁移到不匹配的模型目标；应用配置时会开新会话。
2. 清空旧任务和原生工具上下文，仍在当前作品成果上工作，避免旧指令持续影响。
3. 在同一作品上开展另一项任务，单独保留任务对话，例如审查或规划。但任务产生的写入仍影响作品，不能当成平行试写分支。

压缩没有完全替代第二个用途。`buildAgentMainContext` 的隐藏／总结目前仅过滤独立的 `adopted_prose` 文本消息，再注入摘要；工具结果、原生 assistant 回合、旧状态快照和指令仍保留。它不是对整段执行历史的彻底压缩，旧正文还可能存在于工具结果中。运行器仍有 4 MiB 输入保护。总结本身也不会切换固定的模型与配置。

## 建议

对于持续写作，建议产品层收敛为“作品 + 一条主时间线”，将“新建会话”改为明确的“重置上下文／开始新阶段”：保留作品成果，生成交接摘要，衔接当前剧本进度；旧阶段作为只读历史，不鼓励来回恢复旧上下文继续写入同一当前状态。底层可以继续使用 session 作为模型原生上下文的生命周期，不必立刻删表迁移。

若目标是不同剧情路线、试写比较或独立实验，则应提供显式“分支作品”：正文、剧情状态、剧本进度都独立。现有多会话无法承担这个语义。是否改为单时间线或增加分支属于后续产品决定，本次保持现有会话功能。
