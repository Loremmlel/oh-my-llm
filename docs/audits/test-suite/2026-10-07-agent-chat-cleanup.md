## 保留的不同失败机制

- Agent 权限、工具体积上限、单层委派、原生续接、恢复、事务回滚和无效持久记录均保留；长正文 / 长推理是不同事件路径，不合并掉任一条。
- Agent 存储规模、Chat 大文本刷新隔离保持原始输入规模；鼠标与触摸滚动各有输入路径，继续独立测试。
- 已发布 schema 迁移、持久化失败、图片异步资源取消、通知迟到清理、并发分页结果、编辑事务与会话草稿归属测试均保留。
- Anthropic 文本角色转换保留精确顺序 / 内容的规则矩阵，仅移除最后一条宽泛的“都是合法角色”断言。
- 行覆盖相同不作为去重充分条件；合并场景继续执行原有关键动作，并检查各步可观察结果。

## 测量方法与验证

Windows 原生 PowerShell 7，`dart_test.yaml` 并发 8；前后均用以下同一组带 coverage 命令。墙钟包含 Flutter 命令完整进程时间，reporter 来自 JSON 最后的 `done.time`。每轮测试有 240 秒进程树硬超时，单文件验证为 60 秒，所有日志写入 ignored 的 `logs/`。

```powershell
flutter test --no-pub test/features/agent test/features/chat --coverage --coverage-path=logs/agent-chat-cleanup-<阶段>-scope-<轮次>.lcov --reporter compact --file-reporter=json:logs/agent-chat-cleanup-<阶段>-scope-<轮次>.json
flutter test --no-pub --coverage --coverage-path=logs/agent-chat-cleanup-<阶段>-full-<轮次>.lcov --reporter compact --file-reporter=json:logs/agent-chat-cleanup-<阶段>-full-<轮次>.json
```
