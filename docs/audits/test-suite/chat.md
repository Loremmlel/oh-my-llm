# Chat 测试套件 ponytail-audit

## 范围与数量

- 范围：`test/features/chat/**` 的 66 个文件（50 个 `*_test.dart`、14 个 `*_cases.dart`、2 个 helper），并交叉核对 `lib/features/chat/**`、共享 HTTP/SSE、分页和模板语言测试。
- 当前规模：20,025 个物理行（其中非空代码约 17,630 行）、671 个 `test` / `testWidgets` 注册点；其中大量 widget/Isolate/受控流用例的单例成本明显高于纯函数测试。
- 方法：只读审计测试体和对应生产代码，未修改测试、未运行全量测试。下列净删行数按候选测试块、随之失去用途的局部 fixture/helper 及合并后的代表用例估算。

## 必须保留的覆盖底线

- 消息树：保留纯函数层对 append/replace/级联删除/选择映射的完整契约、SQLite 分支往返，以及一条 controller 与一条 UI 的编辑/切换分支贯通用例；不能只留线性消息 happy path。
- Generation：以 `chat_generation_run_test.dart` 锁定 prepare/stream/retry/stop/finalize/outcome，以 `chat_generation_race_contract_test.dart` 保留少量跨 controller 的 durable-save 竞态；每种终态至少有一个外层投影断言。
- Reasoning / content：三协议 parser 各保留正文与推理分流、usage/finish reason、协议错误；保留一条 client 贯通、`ChatMessage`/SQLite 持久化和 `ReasoningPanel` UI 可达用例。
- Prompt：保留“检查点记忆 → before → 对话（过滤后）→ beforeLatestInput → after”的完整顺序、角色映射、禁用/空模板过滤，以及检查点增量 tail 语义。
- Inline error：保留真实错误、空回复两类 assistant 内联卡片及从卡片重试的 UI 契约；错误不得退化成 SnackBar/Dialog。
- 协议：保留 `LlmApiProtocol.values` 到三个 client 的穷举路由；每个 client 保留请求头/请求体和一条成功流式解析 smoke，传输超时/keepalive/非 2xx 的细节由共享层测试所有。
- 其余关键边界：历史搜索只匹配标题与 user 消息、后台仓库 ACK/flush/close、会话草稿隔离、通知脱敏、关键自绘控件的 Semantics 与至少一种键盘等价操作。
