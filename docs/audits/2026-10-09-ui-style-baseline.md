# UI 风格重构：现状观察与待讨论事项

日期：2026-10-09。基线：`8247af3d`，应用版本 `4.5.21+0`。工作分支：`feat/ui-redesign`。

本文保留从最初观察到方向确认的过程。**最新结论：暖白／绿色与 Anthropic 式字体搭配、开放正文、单套侧向导航及预设独立编辑页已获认可。**正式参考图与约定见 [UI 重构设计基准](../design/ui-redesign/README.md)。下文标为探索阶段的候选意见不是当前仍未决定的事项。

## 目标与分支约定

用户希望改变当前 Material 风格，探索应用整体的新视觉与交互风格。这是本次重构的主要目标；前期发现的信息层级、导航与编辑体验问题作为输入保留，不替代风格探索本身。

- 本次重构的讨论记录、设计文档和后续代码统一在 `feat/ui-redesign` 分支完成。
- 最初阶段只记录现状并讨论方向，尚未选择新设计体系、组件库或技术迁移方案；最终方向见文首链接。
- “安静的阅读与创作工作台”是最初建议，并非用户原话。后续认可的是具体图稿、暖白／绿色与 Anthropic 设计语言。
- 是否保留部分 Material 底层能力、是否替换组件库，待视觉和交互方向明确后决定。
- `DESIGN.md` 已增加新方向入口，其余章节继续描述现有实现；主题和共享组件随代码迁移再更新。
- UI 预览仅使用开发服务与内置浏览器，不操作用户桌面应用。

通过 Flutter Web debug 服务与内置浏览器观察，代表视口为桌面 `1280×900` 和窄屏 `390×844`。全部使用示例数据，未读取个人聊天数据、提交真实模型请求或保存用户配置。

| 对象 | 预览方式 | 可据此判断的范围 |
| --- | --- | --- |
| 聊天 | 实际 `AppShellScaffold`、`ChatMessageBubble`、`ComposerProviderModelRow`、`ComposerMessageField` 的组合预览 | 导航外观、消息气泡和字段外观；不代表完整聊天页、完整 composer 或实际滚动行为。 |

| Agent | 实际 `AgentScreen`，注入示例工作区、文档和无模型状态 | 空状态、工作文档、导航、模型与规则编辑器的呈现；不代表真实运行、持久化或生成流程。 |

预览入口显式加载应用的思源黑体，最终截图使用该字体。组合预览的额外切换按钮、发送禁用状态、页面居中和留白不能作为产品缺陷。Agent 预览曾因示例控制器未提供配置列表而报错，补齐后可打开配置编辑器；该错误属于预览接线，不登记为应用故障。

本次未执行 Windows／Android 原生验收、软键盘验证、流式生成、全套键盘及可访问性测试，也未验证完整应用的页面切换和数据保存。

## 现状观察

以下各项均未实施。表中的改进方向是候选方案，不是已批准的需求或缺陷修复结论。

### 聊天阅读与视觉层级

实际消息组件中，用户消息使用紫色背景，Assistant 回复使用大面积灰色背景，推理入口又有独立浅色容器。长文场景下，多层容器可能增加视觉负担；这属于风格与阅读体验判断，不是功能错误。

可探索的方向：Assistant 正文直接置于阅读画布，用户消息保留轻背景；模型名、字数、推理入口形成较轻的辅助层级。消息是否采用统一阅读列、输入区如何组织模型／模板配置，需要在完整聊天页面中比较方案，不能根据简化组合预览认定当前整页布局有问题。

继续保留的能力：推理与正文分离、消息头部的可达操作、分支与草稿语义、停止入口，以及正文可选择复制。

相关实现：

- `lib/features/chat/presentation/widgets/messages/bubble/chat_message_bubble.dart`
- `lib/features/chat/presentation/widgets/composer/chat_composer_card.dart`
- `lib/features/chat/presentation/widgets/workspace/chat_workspace.dart`

### 复杂编辑器在窄屏中的空间分配

桌面预设编辑器的“左侧条目、右侧编辑”关系清楚，正文获得了较完整的区域。这是可以延续的结构。

在 `390×844` 预览中，弹窗外边距、内部面板和多个纵向字段叠加，正文编辑区出现在较下方，可用宽度也明显缩小。本次没有验证软键盘弹出后的表现，不将其描述为键盘遮挡或控件不可达缺陷。

候选方向：窄屏复杂编辑改用全屏页面，固定返回与保存；条目切换使用独立面板，角色、位置等属性紧凑组织。桌面继续保留左右结构。是否采用此方案，应随新风格统一确定。

相关实现：

- `lib/features/settings/presentation/widgets/prompts/forms/preset_prompt_form_dialog.dart`
- `lib/features/settings/presentation/widgets/shared/settings_form_dialog_scaffold.dart`

### Agent 的创作语言与首次使用引导

实际页面标题为“Agent 小说工作区”，空状态与输入主要使用“任务”“开始任务”“工具调用和子 Agent”等执行术语。作品名、正文、工作文档和剧情状态已经存在，但创作对象与执行机制的主次仍可讨论。

无模型状态下，页面提示在“模型与规则”中选择模型，入口是右上角图标。可以考虑在该状态下直接提供“选择模型”动作，减少寻找入口的步骤。

候选方向：突出作品名称，让人物、世界设定、正文等创作对象更直接；空状态提供明确的下一步。是否将文档／剧情状态改成辅助面板、是否调整“Agent”命名，均待讨论，不预先改变已有工作流。

相关实现：

- `lib/features/agent/presentation/agent_screen.dart`
- `lib/features/agent/presentation/agent_documents_panel.dart`
- `lib/features/agent/presentation/agent_configuration_dialog.dart`

### 服务商展开信息重复

在实际服务商组件中，模型数量同时出现在副标题、展开／收起按钮和详情元信息里；模型名称既出现在摘要，也出现在下方模型列表。截图与源码均可确认这种重复。

候选方向：服务商概况保留一份数量与协议信息，展开后直接显示模型；端点、凭据状态按作用域放入连接详情。保留直接配置模型能力的入口。具体布局随新风格决定。

相关实现：

- `lib/features/settings/presentation/widgets/providers/lists/provider_tile.dart`
- `lib/features/settings/presentation/widgets/providers/lists/provider_info_body.dart`
- `lib/features/settings/presentation/widgets/providers/lists/provider_model_tile.dart`

## 风格讨论的后续输入

下一步首先讨论希望获得的整体气质、控件语言与参考界面，再决定实现方式。需要逐步明确：

- 更接近桌面工具、阅读编辑器、原生系统界面，还是独立的跨平台设计语言。
- 圆角、边框、阴影、选中态、菜单、弹窗、导航和动效如何形成统一风格。
- Windows 与 Android 共用哪些视觉原则，哪些交互需要按可用空间调整。
- 长文阅读与高频配置各自需要的密度，以及浅色／深色下的表现。

用同一份真实内容和同一套功能比较候选样式，避免只靠颜色名称或组件库名称作决定。在方向确定前，不把现状观察自动扩展成全应用导航重构或业务改造。

## 概念图反馈与 Anthropic 参考研究

2026-10-09 用户反馈：

- 最初的 Fluent／中性极简概念图变化太小，像只换了颜色。
- 随后的工作台、书页、悬浮三版均未获认可；其中第一版被认为太像 ChatGPT。
- 书页版的视觉气质有一定吸引力，但页面结构不实用。不能将此理解为已选定书页布局。
- 用户要求研究 Claude／Anthropic 美学，仍处于风格探索阶段。

后续对暖白／陶土色概念图的反馈：

- 用户认可整体风格，但反对侧栏堆叠，认为额外的说明和标语没有必要。
- 色系改为暖白与绿色系；可以参考字体和控件搭配，不照搬 Anthropic 整套配色。
- 新生成两张候选图：聊天使用顶栏导航、历史入口按需展开；预设编辑去掉全局侧栏，只保留条目切换列表。暖白为主背景，灰绿用于选中区域，深绿用于主要操作。
- 顶栏与具体布局是助手提出的待确认方案，尚未作为最终导航规范；概念图未实现为应用代码。

用户进一步澄清与本轮调整：

- 侧栏本身可以使用，反对的是多个侧栏层层叠加；不能将上一轮反馈写成禁止侧栏或必须使用顶栏。
- 用户认可预设编辑放弃弹窗、改为独立页面的方向。
- 新候选图中，聊天将应用入口与最近对话合并到同一侧栏；预设进入独立编辑页面后，同一侧栏位置改为条目列表，并提供“返回预设列表”，不再并列显示全局导航和设置分类。
- 保留暖白／绿色系、字体搭配与精简文案。侧栏的确切宽度、控件比例及编辑页导航细节仍为待评审概念，不代表已经实施。

当前已认可的方向与本轮修正：

- 用户认可单侧栏聊天图，尤其认可主区域的开放正文呈现方式；后续页面以其暖白／绿色、标题与正文层次、弱化气泡容器作为视觉基准。
- 预设编辑维持独立页面。新增、上移、下移放在条目列表顶部；模板语法与预设名称／保存操作同排，不单独占满一行。
- 用户要求扩展主要页面且不能漏功能。本轮按路由、设置页、composer、Agent、收藏、历史、同步与媒体源码建立 [页面与功能对应清单](2026-10-09-ui-concept-coverage.md)。
- 本轮仍是图像概念探索：页面布局与控件样式可供评审，图中生成的虚构数据、错误按钮文案或控件状态不覆盖业务规则。没有修改 Flutter 运行代码。

本次查阅的第一方资料：

- [Geist 为 Anthropic 制作的品牌案例](https://geist.co/work/anthropic)：早期品牌系统使用 Styrene 与 Tiempos 字体搭配，强调温暖色彩、人文插画以及功能优先的 UI 组件。它是历史设计案例，不是当前 Claude 全部页面的实现规范。
- [Anthropic 官方品牌指南](https://github.com/anthropics/skills/blob/main/skills/brand-guidelines/SKILL.md)：公开的基础颜色包括墨黑 `#141413`、暖白 `#faf9f5`、浅灰 `#e8e6dc`、陶土橙 `#d97757`。该指南面向品牌产物，所列 Poppins／Lora 不应直接当作当前产品实际使用的字体。
- [Claude 官网](https://claude.com/)：通过内置浏览器观察到衬线大标题、无衬线导航与按钮、暖白背景、细边框和少量暖橙强调。营销首屏的留白比例不宜直接移植到高频配置页面。

当时用于后续概念生成的候选约束（保留讨论过程，最终约定见设计基准）：

- 保留温暖、安静、书卷气的方向，通过字体角色、平面层级、细分隔线与控件形态共同表达。
- 页面标题缩回工具界面尺度；聊天正文与预设编辑器优先获得空间，不再使用占据主要视口的杂志式大标题。
- 导航与配置使用清晰的无衬线字体；宋体／衬线风格仅作为标题和长文阅读的候选，不能默认套到所有中文正文与控件。
- 预设编辑维持一套条目导航与大面积编辑区，常用属性就近排列，不再同时使用重复的横向标签与侧边目录。
- 新概念应使用多条会话、长正文、多个预设条目和展开配置等真实密度，验证其视觉效果与空间分配。

主要页面图组完成后的确认：

- 用户认可最终图组，要求将参考图片、意见和 Anthropic 设计思路随分支提交。
- 风格尽量模仿 Anthropic，仅采用不同色调；继续使用暖白与绿色系。
- 字体角色区分必须覆盖中文。用户接受多个中文字体及较大的包体，允许裁剪后打包，明确希望超过约 3000 字。
- 助手建议以《通用规范汉字表》完整 8105 字作为裁剪起点；具体字族与字集执行方案仍须经过样张、覆盖和性能验证，未写成已实施决定。
- 11 张认可参考图现已保存在 [docs/design/ui-redesign/references](../design/ui-redesign/references/)，以 Git 版本管理；具体实施步骤留待讨论。
