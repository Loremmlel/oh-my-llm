# 测试约定

适用于测试及辅助代码。先读根 [AGENTS.md](../AGENTS.md)、[执行与日志指南](../CONTRIBUTING.md) 和被测领域规则。

## 选择与维护

- 按业务重要性选择验证。重点保护聊天发送、流式、停止与恢复，消息分支和草稿隔离，协议编码解析及工具回放，持久化、迁移、失败回滚和重要安全边界。
- 低风险文案、样式、小配置、简单 getter、构造器、字段转发和框架默认行为允许不新增自动化测试。基础可访问性、产品行为、凭据处理与数据保护仍须实现，不自动扩成逐字段、逐平台、逐组件矩阵。
- 修复 bug 本身不是新增回归测试的理由。优先运行、修改或补强已有相关测试，也可用一次针对性检查或必要手工验证。只有核心或重要行为有新的独立覆盖缺口才增加最小用例，新增测试文件是最后选择。
- 同一规则主要在一个合适层级保护；上层只保留真实接线或生命周期独有的少量场景，不复验下层输入矩阵。测试实际输入输出和状态变化，不测 fake 自身或私有实现。
- 低价值测试可以直接删除，接受其不再受自动化保护，不要求替代 owner、逐项覆盖归属说明或覆盖率账本。已发布数据库迁移、合法旧数据 fixture 和关键数据保留语义按持久化规则保留。
- 红绿验证按实际需要使用，不强制先失败后成功、临时撤回修复或保存成对日志。

## 执行

- 日常迭代运行受影响的现有测试；涉及广泛影响或最终整体验收时执行全量，不在修改几行后反复全量运行。
- 性能清理通常用一次同环境基线与一次最终对照；仅波动或失败影响结论时补测。必要时用 JSON reporter 定位开销，不固定要求多轮全量或逐分支覆盖率审计。
- 使用 `scripts/run-tests.ps1` 保留清晰退出码、日志和进程超时。验证完成后停止，不为“更稳妥”扩大范围。

## 准备与异步

- 纯函数直接调用；纯组件使用最小 MaterialApp / Material；需要 Provider 时只注入必要依赖。仅真实持久化或应用接线场景使用 [pumpTestApp](helpers/test_harness.dart) 和 SQLite。
- 复用现有简单 helper、[TestFixtures](helpers/fixtures.dart) 和 fake，不建立通用测试框架或大量开关。有效数据可用模型工厂，协议、迁移和 malformed 边界可直接写原始数据。
- 异步优先等待 Provider 状态、受控 stream、Completer、Repository ACK 或 IO Future 等完成信号。有限动画可直接 `pumpAndSettle()`；不要以任意延迟或无条件 settle 代替完成信号。
- finder 优先可见文本、Semantics 和稳定交互，不依赖内部 widget 结构或像素位置。测试必须执行到断言，不用条件 early-return 掩盖未验证分支。
- 名称和注释用简体中文。连贯用户操作可合并成少量场景，不按行数机械拆分。
- 只有 `*_test.dart` 自动发现；现有 `*_cases.dart` 必须由有效入口注册。删除或合并入口时同步清理失去引用的 helper、fixture 和 import。
